# Kantai Collection Map 1-1 Design Philosophy

## Map Overview
**World 1-1: 鎮守府海域 (Naval District Waters)** - The tutorial map introducing basic game mechanics.

### Purpose
- **Tutorial Introduction**: First map players encounter, designed to teach basic gameplay
- **Resource Farming**: Early-game resource collection (fuel, ammo)
- **Ship Leveling**: Low-level ship training
- **Drop Farming**: Common ship drops for early roster building

### Difficulty
- **Rank**: Trivial (Easiest map in the game)
- **Recommended Level**: Level 1-10 ships
- **Resource Cost**: Minimal (low fuel/ammo consumption)
- **Repair Cost**: Minimal damage taken

### Unlock Requirements
- **Initial Unlock**: Available from game start
- **No special requirements**: Open to all players immediately

## Node Layout

### Visual Structure
```
Start → Node A (Scout Combat) → Branch Point
                         ↳ Node B (Stray Fleet) → Sortie End
                         ↳ Node C (Boss) → Sortie End
```
Probabilistic branching based on fleet size at Node A.

### Node Details (Based on Kancolle Wiki)
1. **Node A: 敵偵察艦 (Enemy Scout Ships)**: Initial combat encounter
   - **Type**: Combat node (always encountered)
   - **Purpose**: Introductory battle teaching basic mechanics
   - **Branch Point**: From here, fleet proceeds to either Node B or Node C based on fleet size probability

2. **Node B: 敵はぐれ艦隊 (Enemy Stray Fleet)**: Secondary combat encounter
   - **Type**: Optional combat node
   - **Purpose**: Additional experience/resources if boss is not reached
   - **Progression**: Ends sortie after combat

3. **Node C: ボス敵主力艦隊 (Boss Enemy Main Fleet)**: Primary objective
   - **Type**: Boss combat node (map clear condition)
   - **Purpose**: Map completion reward and better drops
   - **Progression**: Ends sortie after combat (win or lose)

### Node Types
- **Combat Nodes**: All three nodes feature combat (no resource/air raid nodes)
- **Branching Node**: Node A serves as both combat and routing decision point
- **Terminal Nodes**: Both Node B and Node C end the sortie after combat

## Routing Rules

### Branching Conditions (Based on Kancolle Wiki "ルート分岐法則" section)
Map 1-1 features **probabilistic routing** based on fleet size:

**Node A (Start/Scout) → Branch**:
- From starting node A, fleet proceeds to either:
  - **Node B (Stray Fleet)** - Combat encounter
  - **Node C (Boss)** - Direct to boss (bypasses Node B)

**Probability to proceed to Node C (Boss)** depends on fleet size:
- 6 ships: 55% chance to go to Node C
- 5 ships: 60% chance to go to Node C  
- 4 ships: 65% chance to go to Node C
- 3 ships: 70% chance to go to Node C
- 2 ships: 75% chance to go to Node C
- 1 ship: 80% chance to go to Node C

**If not proceeding to Node C**, fleet goes to Node B (Stray Fleet) for an additional combat encounter before potentially ending the sortie.

### Design Intent
- **Tutorial Accessibility**: Smaller fleets (new players) have higher boss access rates
- **Farming Control**: Larger fleets (experienced players) have more predictable routing for resource/drop farming
- **Risk-Reward Balance**: More ships = more combat power but lower boss chance

### No Special Requirements
- **No LOS requirements**: Line of Sight not checked
- **No fleet composition restrictions**: Any ship types allowed
- **No speed requirements**: All speeds allowed
- **No drum/transport requirements**: Not applicable

### Fleet Considerations
- **Single Fleet**: Surface Task Force only (no Combined Fleet mechanics)
- **Ship Limit**: 6 ships maximum (standard fleet size)
- **No locking**: Ships not locked to this map
- **Fleet Size Strategy**: Players can adjust fleet size to control boss access probability

## Enemy Analysis (Based on Kancolle Wiki "敵編成" section)

### Node A: 敵偵察艦 (Enemy Scout Ships)
**Purpose**: Introductory combat encounter teaching basic battle mechanics.

**Patterns**:
1. **Pattern 1 (10 EXP)**: 駆逐イ級 (Destroyer I-class) ×1 - Single weakest destroyer
2. **Pattern 2 (15 EXP)**: 駆逐ロ級 (Destroyer Ro-class) ×1 - Slightly stronger destroyer  
3. **Pattern 3 (20 EXP)**: 駆逐ハ級 (Destroyer Ha-class) ×1 - Basic destroyer variant

**Design Notes**:
- Single enemy ship minimizes complexity for new players
- Gradual EXP increase introduces progression concept
- All patterns use 単縦陣 (Line Ahead) formation - teaches basic formation mechanics

### Node B: 敵はぐれ艦隊 (Enemy Stray Fleet)
**Purpose**: Secondary combat encounter for additional rewards/experience.

**Patterns**:
1. **Pattern 1 (20 EXP)**: 駆逐イ級 ×2 - Two weakest destroyers
2. **Pattern 2 (30 EXP)**: 駆逐ロ級 ×2 - Two basic destroyers
3. **Pattern 3 (40 EXP)**: 駆逐ハ級 ×2 - Two stronger destroyers

**Design Notes**:
- Two-ship encounters introduce multi-target combat
- EXP values scale appropriately (2× Node A EXP)
- Maintains 単縦陣 formation consistency

### Node C: ボス敵主力艦隊 (Boss Enemy Main Fleet)
**Purpose**: Map clear condition with slightly increased challenge.

**Patterns**:
1. **Pattern 1 (50 EXP)**: 軽巡ホ級 (Light Cruiser Ho-class) ×1 + 駆逐イ級 ×2
2. **Pattern 2 (60 EXP)**: 軽巡ホ級 ×1 + 駆逐ロ級 ×2  
3. **Pattern 3 (70 EXP)**: 軽巡ホ級 ×1 + 駆逐ハ級 ×1 + 駆逐ロ級 ×2

**Design Notes**:
- Introduces light cruiser enemy type (higher durability/firepower)
- Mixed fleet compositions teach target priority
- EXP progression: 50 → 60 → 70 provides clear reward scaling
- Boss patterns feature 3-4 ships total, manageable for starter fleets

### Difficulty Progression
- **Enemy Tier**: Basic destroyers (I/Ro/Ha-class) → Light cruiser (Ho-class)
- **Fleet Size**: 1 ship → 2 ships → 3-4 ships
- **EXP Values**: 10-20 → 20-40 → 50-70 (clear progression curve)
- **Formations**: Consistent 単縦陣 (Line Ahead) throughout
- **Threat Level**: Minimal but introduces gradual complexity

## Resource Nodes

No resource nodes present in map 1-1. Resource collection comes from:
- Post-battle resource rewards (minimal)
- Map clear bonuses

## Drop Analysis (Based on Kancolle Wiki "ドロップ" section)

### Drop Tiers by Node
- **Node A (Scout)**: Basic destroyers (睦月型, 吹雪型, 綾波型, etc.)
- **Node B (Stray Fleet)**: Basic destroyers + light cruiser (神通, 那珂)
- **Node C (Boss)**: Expanded destroyer pool + light cruisers (天龍, 龍田) + rare ships

### Design Patterns
- **Progressive Unlocks**: Better ships available at later nodes
- **Early Game Roster Building**: Common destroyers help new players build fleet
- **Boss Incentive**: Better drops encourage boss attempts
- **Farming Strategy**: Players can farm Node B for specific ships if boss chance is low

### Notable Drops
- **Common**: Various destroyer classes (starter ship availability)
- **Uncommon**: Light cruisers (天龍, 龍田, 川内型)
- **Rare**: Seasonal/event ships may appear during special campaigns

## Design Patterns Observed

### Tutorial Design Elements
1. **Guided Progression**: Probabilistic branching favors new players (smaller fleets → higher boss chance)
2. **Gradual Complexity**: Single enemy → two enemies → mixed fleet progression
3. **Low Risk**: Minimal resource cost and damage potential encourages experimentation
4. **Immediate Feedback**: Quick sorties with visible probability outcomes

### Adaptive Difficulty System
- **Fleet Size Probability**: Game adapts to player's fleet strength (fewer ships = easier boss access)
- **Scaling Rewards**: EXP values increase predictably (10→20→50) based on encounter difficulty
- **Controlled Randomness**: Random enemy patterns within predictable tiers

### Farming Mechanics
- **Controllable Routing**: Players can adjust fleet size to influence boss access rates
- **Efficient Resource Farming**: Node B provides additional resources/EXP when boss is missed
- **Drop Tiering**: Basic destroyers (A/B nodes) vs. light cruisers (C node) for progression

### Psychological Design
- **Success Assurance**: High boss access for small fleets builds early confidence
- **Controllable Risk**: Players understand probability system and can optimize strategies
- **Reward Visibility**: Clear EXP progression and ship drop tables provide tangible rewards
- **Learning Through Repetition**: Multiple sorties teach combat mechanics without punishment

## Implementation Notes for FleetMemories

### Adaptation Considerations
1. **Tutorial Function**: Maintain introductory role with probabilistic branching
2. **Adaptive Difficulty**: Consider implementing fleet-size influenced routing
3. **Enemy Scaling**: Match early-game progression (1 → 2 → 3-4 enemies)
4. **Reward Structure**: Provide clear EXP/drop progression based on node
5. **Probability Transparency**: Consider showing boss chance to players

### Suggested FleetMemories Implementation Options

**Option 1: Simplified Deterministic** (Easier Implementation)
- **Node Count**: 3 nodes (Start → Scout → Boss)
- **Enemy Strength**: Tier 0-1 enemies with gradual scaling
- **Routing**: Fixed linear path for tutorial simplicity
- **Rewards**: Basic equipment/ship drops with clear progression

**Option 2: Probabilistic Branching** (Closer to Kancolle)
- **Node Count**: 3 nodes with A→(B or C) branching
- **Probability System**: Fleet size affects boss chance (6 ships: 55% → 1 ship: 80%)
- **Enemy Design**: Scout (1 enemy) → Stray (2 enemies) → Boss (3-4 enemies)
- **Reward Tiers**: Different drop tables per node (common → rare)

**Option 3: Hybrid Approach**
- **Deterministic First Clear**: Guaranteed boss for first few sorties (tutorial)
- **Probabilistic Thereafter**: Introduce branching after tutorial completion
- **Adjustable Difficulty**: Let players choose fleet size strategy

4. **Forgiveness**: Low resource cost and minimal failure consequences
