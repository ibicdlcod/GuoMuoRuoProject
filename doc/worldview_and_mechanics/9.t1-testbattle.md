# Test Battle Mode

## Command-line interface

```
CFServer --testbattle <path.lua> [--report <path.md>] [--repeat <N>]
```

Runs a battle from a Lua configuration file without requiring a Steam
connection, networking, or persistent database.  Uses an in-memory SQLite
database.

| Flag           | Description                                      |
|----------------|--------------------------------------------------|
| `--testbattle` | Path to Lua test file (required)                 |
| `--report`     | Output markdown report path                      |
| `--repeat`     | Number of runs for aggregate statistics          |

`--report` is required when `--repeat` > 1; otherwise the program fails
with a warning.

[Implemented in main.cpp#test-battle-mode]

## Lua test file format

The Lua file must return a table with at least `FriendFleetInfo` and
`EnemyFleetInfo` tables.  An optional `BattlePlan` table overrides
defaults.

See `test/example.lua` for a complete, executable example.

### FriendFleetInfo / EnemyFleetInfo

| Key                 | Description                                                |
|---------------------|------------------------------------------------------------|
| `ships`             | Table mapping fleet position (0-based) → ship def ID       |
| `shipDynamics`      | Per-ship state table (see below)                           |
| `shipTags`          | Optional tag vector (defaults to all zeros)                |
| `equipSkillEffects` | Optional equip def ID → skill effect multiplier map        |
| `type`              | Fleet type (default 0 = NormalFleet)                       |

**shipDynamics[pos]** — per-ship dynamic state:

| Key            | Description                                                      |
|----------------|------------------------------------------------------------------|
| `lv`           | Ship level (exp is derived automatically)                        |
| `slotEquip`    | List of equip def IDs (0 = empty, UUIDs are generated)           |
| `slotEquipEx`  | EX slot equip def ID (0 = empty)                                 |
| `slotPlanes`   | Plane counts per slot (optional; derived from equip if omitted)  |
| `fuel`         | Fuel fraction 0.0–1.0 (default 1.0)                              |
| `ammo`         | Ammo fraction 0.0–1.0 (default 1.0)                              |
| `currentHP`    | Override max HP (default from ship attr)                         |

If `slotEquip` is omitted for any position, the ship's default
equipment (from `Ship::getStartingEquip()`) is loaded automatically.

### BattlePlan (optional)

| Key                          | Description                           |
|------------------------------|---------------------------------------|
| `friendFleetPriority`        | KP::FriendFleetPriority (default 0)   |
| `enemyFleetPriority`         | KP::EnemyFleetPriority (default 0)    |
| `extraBattle`                | Enable extra battle (default true)    |
| `extraBattleWhenLosing`      | (default false)                       |
| `extraBattleWhenFlagship`    | (default false)                       |
| `extraBattleWhenBorBelow`    | (default false)                       |
| `extraBattleWhenAorBelow`    | (default false)                       |

## Fleet construction

[Implemented in Server::buildFleetFromLua]

Ships are looked up from the `shipRegistry` by def ID.  Equipment UUIDs
are generated randomly.  Experience is derived from level using the
standard `Ship::getLevel()` inverse formula.  When `slotEquip` is omitted,
default equipment is loaded via `Ship::getStartingEquip()` and
registered in the fleet's `equipMap` with fresh UUIDs — the same
mechanism used by `Server::createEnemyFleetInfo()`.

## Single-run report (`--report`)

[Implemented in Server::writeMarkdownReport]

Produces a markdown file containing:
- Fleets table (initial HP)
- Per-event battle log (clock time, attack type, attacker/defender names,
  damage, evasion, non-penetration, overpenetration, cut-in multipliers)
- Air superiority and formation efficiency values
- Results table (final HP)

Attack types are labelled per `typeLabelForReport()`.  Cut-in types
(spotting fire, plain gun, torpedo, gun-torpedo) are differentiated
via the `cutInType` field from the damage log.

## Aggregate report (`--repeat`)

[Implemented in Server::writeAggregateReport]

Runs the battle N times with independent RNG states.  Accumulates
per-ship per-attack-type statistics and produces:
- Average damage dealt / taken per ship
- Damage composition by attack type per ship (differentiated cut-in
  variants)
- Hit rates (hits / total attempts) by base attack type per ship
- Global averages for air superiority coefficient and formation efficiency

The `RunStats` struct in `server.h` holds per-run data.  Statistics
are collected by scanning the damage log for attack, evasion,
non-penetration, air-superiority, and formation-efficiency entries.
