# Air-battle-only node

An **air-battle-only node** (`isAirOnly = true`, set via `BattlePlan.isAirOnly`)
skips all surface combat phases — only the air battle phase runs. This
represents map nodes where enemy air power contests the fleet's passage
without surface engagement (e.g., air raids, interceptions, orland-based
air strikes).

[Implemented in Battle::battleProcessor#air-battle-only]

## Phase flow

1. Air battle commences with `clock = 0`
2. Air superiority is computed and plane losses are processed (S1, S2, S3)
3. Opening airstrikes launch from both fleets
4. The battle ends — no approaching, central, disengaging, or night phases

## Bombers grounded tactical goal

Valid **only** for air-battle-only nodes. When `friendGoal =
FriendAntiAir`, bombers stay grounded:

- Fighters prioritize air superiority interception over escort/offensive
  operations
- Bombers do not launch offensive strikes
- The fleet focuses purely on shooting down enemy planes rather than
  dealing ship damage

This is set via the `BattlePlan`:

```json
{
    "friendFleetPriority": 4,  // FriendAntiAir = bombers grounded
    "isAirOnly": true
}
```

The `FriendAntiAir` priority has no special effect on non-air-only
battles — it only activates when `isAirOnly = true`.

## Extra battle decision

Air-battle-only nodes do not trigger extra battles. The phase ends
immediately after the air battle concludes. The `extraBattle` flag from
the battle plan is ignored.

## Usage in map Lua

```lua
maps[id][node] = {
    battle_type = maps.Battle_type.AIR,  -- maps to isAirOnly = true
    ...
}
```

The `Battle_type.AIR` node type signals the server to set `isAirOnly =
true` in the battle plan.
